## 为什么白酒有天天估值，医药和先进制造没有

**源端估值**是数据平台给出的盘中估算价格（人民币份额通常为元/份），不是基金公司公布的正式单位净值。**本地推算**是本项目根据披露持仓或关联标的行情计算的参考值；两者分别标识，不能把推算伪装成平台直接提供的数据。

直接核对天天 H5 `FundValuationLast` 的原始字段，而非只看网页或解析后的表格：

| 基金 | 天天 GSZ / GSZZL / GZTIME | 新浪估值；涨跌幅；行情时刻 |
|---|---|---|
| 012414 招商中证白酒指数 C | 0.5238 / -0.38% / 14:32 | 0.5243；-0.2933%；14:31 |
| 015916 永赢医药创新智选 C | 三项均为 null | 1.5785；-0.3795%；14:32 |
| 018125 永赢先进制造智选 C | 三项均为 null | 1.6294；-3.3466%；14:32 |

以上时刻均为 2026-10-14 上海时间，只是采样快照。医药 A `015915`、先进制造 A `018124` 的天天三项估值字段也为空，但有已公布正式净值。因此：

- 不是前端把这两只基金的估值丢了，也不是只缺某个 C 类份额。
- 样本中的白酒是指数型基金，医药、先进制造是主动混合型基金；这与本轮覆盖差异相符，**但不足以证明平台仅按基金类型开关估值，更不能据此宣称监管要求全行业停供**。
- 尚无已核实公告解释平台的具体取舍。其他指数/联接也不是全部有天天估值，不以行业名称推定接口覆盖。

基金类别及策略可核对[白酒基金档案](https://fundf10.eastmoney.com/jbgk_012414.html)、[医药基金档案](https://fundf10.eastmoney.com/jbgk_015916.html)、[先进制造基金档案](https://fundf10.eastmoney.com/jbgk_018125.html)。

## 新浪的字段与接入方法

依据是[新浪自身基金页面脚本](https://n.sinaimg.cn/finance/fund/quotes/index.js)中的 `latestValuation`，不是其他开源项目的字段猜测。本轮脚本映射检查全部通过，SHA256 记录在 JSON 中。

| 内容 | 读取字段 | 处理 |
|---|---|---|
| 盘中估值 | `fu_CODE[2]` | 正数、有限值；与基准净值及涨跌幅做舍入容差检查 |
| 盘中涨跌幅（%） | `fu_CODE[6]` | 不读取末尾另一组 `[8]/[9]` |
| 实际行情时刻 | `[7]` 日期 + `[1]` 时间 | 上海日期、未来时刻与报价年龄校核；不用抓取时间刷新旧行情 |
| 正式单位净值与日期 | `f_CODE[1]`、`f_CODE[4]` | 与估值分别保存，必须有有效公布日期 |
| 累计净值 | `f_CODE[2]` | 只作独立披露字段，不用于当前份额计价 |
| 正式日增长率 | 此行情未提供 | 保留未知；不以单位净值比值冒充可能含分红调整的正式日增长率 |

请求使用 `https://hq.sinajs.cn/list=f_CODE,fu_CODE,...`，附新浪财经 Referer，按 GB18030 解码，每批最多 100 个代码；只解析精确代码的字符串赋值，绝不执行远程 JavaScript。

**这里有一个已复现的接口陷阱：该服务未按预期解码 `%2C`。** 普通 `requests` 查询参数会把逗号转义，上游可能 HTTP 200 却返回一个含 `%2C` 的不存在标的。现按新浪页面方式保留字面逗号，并有实际请求 URL 的回归测试；HTTP 200 不再作为有效估值的充分条件。

默认只对天天缺少当前估值的代码批量请求新浪，不覆盖已有的天天有效估值。新浪失败/过期时，保留已取得的正式单位净值元数据，再交由显示策略判断是否推算；同日单位净值明显冲突时拒绝采用新浪估值，人工源对比执行相同校核。

**显示规则不变：**盘中不自动显示昨日净值；上海收盘后且当天正式净值已公布才自动切换。`view=nav` 仍可手动查询已公布净值，`view=provider` 不混入本地推算。新浪估值不能覆盖已取得的更新净值日。

## 加载耗时与并发

本轮通过 `http://127.0.0.1:3000/api` 代理实测，第一次请求前应用内存缓存 `size=0`：

| 阶段 | 耗时 | 覆盖 |
|---|---:|---|
| 本地持仓元数据 | 54.0 ms | 18 条，无网络估值依赖 |
| 23 只源端估值 | 412.9 ms | 天天 3、新浪 20 |
| 后续 auto 选择 | 26.6 ms | 本轮无需 F10 推算 |
| 两阶段报价合计 | **439.5 ms** | 23/23；持仓 18/18 |
| 报价缓存命中，两阶段合计 | 17.4 ms | 同一批代码 |

不包含浏览器绘制、图表和源对比详情请求；应用空缓存也不代表上游/CDN 空缓存。没有进行受控 A/B、长期压力测试或 P95 测试，不能将本轮 0.44 秒承诺为每次启动耗时。接入新浪前含 F10 推算的记录仍见[原加载诊断](LOADING_DIAGNOSTICS_20261014.md)。

生产请求是**按需分阶段串行、每阶段批量查询**：天天批量 → 缺估值项的新浪批量 → 仍缺正式净值项的 NAV 备用；随后才对必要项推算。不是逐只基金把六个源轮询一遍，也不是六个源全部竞速。人工“数据源对比”才并发检查六条接口，展示“估值数量”与“可用接口数量”，避免把五条正式净值响应误称为五个实时估值源。

## 使用与复查

- 继续使用原浏览器的 [3000 首页](http://127.0.0.1:3000/home)，按 `Ctrl+F5` 后点刷新，无须删设置或持仓。不要为了刷新改换 `localhost`/`127.0.0.1`，两者本地存储互不相同。
- 白酒优先显示天天来源；医药、先进制造本轮显示“新浪”。若两家都无有效估值而本地推算可用，显示蓝色“推算”；无值与接口异常分别显示警告/错误。
- 当前数据源对比：白酒 2 条实时估值、6 条有效接口；医药、先进制造各 1 条实时估值、6 条有效接口。这是本轮状态，不是长期保证。

仓库根目录、既有命名环境中可重复运行：

```powershell
conda activate fund-tracker
python -B .\data-source-test\check_estimate_coverage.py --rounds 2 --interval-seconds 15 --api-base http://127.0.0.1:3000/api
```

该脚本复用生产解析器，保存原始字段、实际行情时刻、脚本映射证据和可选 API 计时；不增删持仓/关注，不保存持仓金额或份额。`check_availability.py` 仍用于更广的净值、历史与退役接口检查，旧库级基准分数不能代替这些证据。
