## “全部加载”包含什么

- **源端估值**：数据服务直接给出的盘中估算价格，通常人民币份额为元/份，不是基金公司正式公布的单位净值。
- **推算估值**：使用披露持仓或关联标的的真实行情，外推基金价格的参考值；带披露日、行情时刻及假设，不等同于源端估值。
- **加载完成**：本次关注/持仓列表及其报价记录返回，缺少报价的记录仍返回 `null`。历史图表、数据源对比和人工替代方案详情按交互另行加载，不预先下载全市场历史。

| 早期独立冷服务探测 | 18 只，尚未加入 F10 访问间隔 | 0.146 s 直接报价 + 0.824 s 推算 | 可在任意并发下持续高速抓取 |

## 是并发还是逐个失败后切换

**两者都有，不是五个完整数据源一起竞速。**

1. 关注列表与持仓元数据并发读取；均只读本地文件/数据库。
2. 合并、去重代码，先请求 `view=provider`，立即把直接报价放入页面状态。
3. 没有直接估值的代码再请求 `view=auto`；收盘后当天正式净值已公布的记录也交由 `auto` 执行官方净值选择规则。
4. 当时后端报价主链（现已替换）：天天基金 H5 批量 → 缺估值项的新浪批量 → 缺正式净值项的东方财富移动端 → 仍缺项的备用单位净值查询。阶段间按需串行；最后的单基金备用链在基金之间最多并发 4 个。主/备用域名及腾讯/历史/页面备用查询也是按失败或缺项切换，不是都抓完再选。
5. 自动推算在一批内最多并发 4 只基金；单基金的披露持仓推算和关联标的推算并发。同一事件循环中重叠客户端的同代码、相同候选查询模式的推算共享进行中的任务。
6. **人工“数据源对比”才会并发检查六条接口（含新增新浪）。** 多条东方财富接口属于同一上游，可用的正式净值不计为实时估值；两种数量分别展示。

## 为什么截图仍可能看起来“不行”

- 截图显示 **关注 0 只、持仓 18 条**：首页表格使用关注列表，持仓并不自动成为关注项。两种列表分开保存；不同浏览器、`localhost` 与 `127.0.0.1` 的本地存储也不能假定相同。本次没有替用户添加关注或清空缓存。
- 截图里的 `OPTIONS 200` 是预检，不证明 POST 批量报价完成。核查时跨域响应头正常、直连和代理均可请求；**不足以确定原浏览器失败就是 CORS**。默认同源代理现在可避免这条额外预检路径。
- 某些基金缺少免费源端估值；披露持仓也可能受限流或缺少新鲜、足够覆盖的行情影响。`--` 必须与 HTTP 请求失败分开看。
- `auto` 不会在盘中把前一日正式净值冒充当前估值。只有上海收盘后、当天净值已发布才自动显示净值；旧正式净值仍可手动选择。

**请在原浏览器按 Ctrl+F5，再点刷新。** 若仍显示请求失败，需要最新截图或控制台第一条红色错误来核对原会话，勿发送 API Key。不建议先删除设置、数据库或持仓。

## 可继续优化，但不应现在大重写

1. **优先合并关联标的行情**：一批基金共享一份证券行情快照，减少重复腾讯查询并统一统计时刻；先测请求数、P50/P95 和有效估值覆盖率。
2. **延迟加载图表和组件包**：本次生产构建 ECharts 约 346 kB gzip、Element Plus 约 360 kB gzip，按需加载有机会改善首次进入页面；这不解决数据源限流。
3. **为智能体复用同一契约**：保留 `provider/auto/nav`、报价日期/来源、推算标记与缺失原因，支持去重批量查询；将报价核心接给 HTTP/MCP/CLI，skill 只负责调用和解释，不另写一套选价逻辑。
