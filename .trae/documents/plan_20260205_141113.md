# 基金跟踪器模块架构优化计划

## 📋 优化目标
实现首页、基金筛、基金对、持仓管理四个模块的**完全联通、数据互通、共用一套数据库**，消除无效请求和重复请求。

---

## 🔍 当前架构问题分析

### 1. 数据流问题
- **重复请求**：初始化时持仓基金实时数据被请求两次
- **缓存闭塞**：前后端缓存独立，同步困难
- **服务职责不清**：fund_service 与 portfolio_service 存在隐式依赖

### 2. 功能缺失
- **基准指数数据**：/compare 接口未完整支持基准指数
- **实时推送**：缺少 WebSocket/SSE 推送机制

---

#### 1.2 优化缓存策略

**统一缓存 Key 规范：**
```
realtime:{code}              → 60秒
history:{code}:{range}       → 3600秒
benchmark:{symbol}:{range}    → 3600秒
screening:{direction}:{days}:{pct}  → 300秒
```

**消除重复请求机制：**
```python
# 使用分布式锁防止并发重复请求
async def get_realtime_data_cached(self, code: str) -> FundRealtimeData:
    lock_key = f"lock:realtime:{code}"
    async with self.redis.lock(lock_key, timeout=10):
        # 双重检查缓存
        cached = await self.cache.get(f"realtime:{code}")
        if cached and not self._is_expired(cached):
            return cached
        # 获取数据并缓存
        data = await self._fetch_from_source(code)
        await self.cache.set(f"realtime:{code}", data, 60)
        return data
```

### 第二阶段：前端数据层优化

#### 2.1 重构 `dataManager.ts`

**优化初始化流程，消除重复请求：**
```typescript
async initialize(): Promise<void> {
  console.log('[DataManager] 初始化数据...')
  
  // 1. 加载基金列表
  await this.loadFundList()
  
  // 2. 加载持仓数据（包含持仓基金的实时数据）
  await this.loadPortfolio()
  
  // 3. 只加载非持仓基金的实时数据，避免重复
  const portfolioCodes = state.portfolioItems.map(p => p.fund_code)
  const nonPortfolioCodes = state.fundList.filter(
    code => !portfolioCodes.includes(code)
  )
  
  if (nonPortfolioCodes.length > 0) {
    await this.loadRealtimeData(nonPortfolioCodes)
  }
}
```

#### 2.2 统一数据获取逻辑

**创建统一数据钩子：**
```typescript
// hooks/useUnifiedData.ts
export function useUnifiedData() {
  const dataManager = useDataManager()
  
  // 获取基金数据（自动关联持仓）
  const getFundData = async (code: string) => {
    return await dataManager.getFundDataWithCache(code)
  }
  
  // 获取筛选结果
  const screenFunds = async (params: ScreenParams) => {
    return await fundApi.screen(params)
  }
  
  // 获取对比数据（包含基准指数）
  const compareFunds = async (codes: string[], range: string) => {
    return await fundApi.compare(codes, range, true)
  }
  
  return { getFundData, screenFunds, compareFunds }
}
```

### 第三阶段：模块功能完善

#### 3.1 首页模块（HomeView.vue）

**数据流：**
```
dataManager.fundList → fundStore → HomeView
                 ↓
        dataManager.realtimeData（自动关联）
```

**功能**：显示基金列表 + 实时估值 + 涨跌状态

#### 3.2 基金筛模块（ScreenView.vue）

**功能**：筛选连续涨跌基金
```
前端请求 → /funds/screen?direction=up&days=2&pct=0.03
                          ↓
                   后端调用 screen_funds()
                          ↓
                   返回满足条件的基金列表（含历史分析）
```

**筛选逻辑（来自 fund_main.py）：**
```python
def screen_funds(self, direction: str, min_days: int, min_pct: float):
    # 分析每只基金的历史趋势
    # 返回连续上涨/下跌 >= min_days 天或累计幅度 >= min_pct 的基金
```

#### 3.3 基金对比模块（CompareView.vue）

**功能**：多基金累计涨跌幅对比图
```
前端请求 → /funds/compare?codes=xxx,yyy&range=1M&include_benchmark=true
                          ↓
                   后端返回：
                   - 各基金的历史净值数据
                   - 基准指数数据（上证指数、沪深300）
                          ↓
                   前端渲染叠加对比图
```

**图表模式（PlotManager）：**
- Mode 1：多基金累计涨跌幅叠加图（含基准指数）
- Mode 2：多子图分别显示真实净值走势

#### 3.4 持仓管理模块（PortfolioView.vue）

**数据流：**
```
dataManager.portfolioItems 
    ↓ 关联 → dataManager.realtimeData
    ↓ 计算 → 持仓收益、收益率、总资产
```

**功能**：显示持仓 + 自动计算收益 + 关联实时净值
