## 当前架构问题分析

根据代码分析，发现了以下核心问题：

***

### 问题1：数据孤岛 - 各模块独立管理数据

**现状：**
- **首页 (HomeView)**: 使用 `fundStore.fundList` 和 `fundStore.realtimeData`
- **基金筛选 (ScreenView)**: 依赖 `fundStore.fundList` 和 `fundStore.screenFunds()`
- **基金对比 (CompareView)**: 独立调用 `fundApi.compare()`
- **持仓管理 (PortfolioView)**: 使用 `portfolioStore.items` 和 `portfolioStore.stats`

**问题：**
- 各模块独立获取数据，造成重复请求
- 基金实时数据在多个地方重复获取
- 持仓数据和基金数据没有关联

***

### 问题2：重复请求

**现状：**
- 首页加载时调用 `fundStore.fetchRealtimeData()`
- 切换到持仓管理时，又独立获取持仓数据
- 持仓中的基金实时数据没有与首页共享
- 每次切换模块都重新请求数据

**问题：**
- 同一基金的数据被多次请求
- 没有有效的缓存共享机制
- 网络资源浪费

***

### 问题3：数据不一致

**现状：**
- 首页显示的基金实时数据
- 持仓管理显示的基金实时数据
- 两者来自不同的API调用

**问题：**
- 同一基金在不同模块显示不同数据
- 数据更新不同步
- 用户体验不一致

***

### 问题4：缺乏统一的数据管理层

**现状：**
- `fundStore` 管理基金列表和实时数据
- `portfolioStore` 管理持仓数据
- 两个store之间没有关联

**问题：**
- 数据分散管理，难以维护
- 状态同步困难
- 代码重复

***

## 优化方案

### 架构目标

1. **单一数据源 (Single Source of Truth)**
   - 基金实时数据只在一个地方获取和存储
   - 所有模块共享同一套数据

2. **按需加载 (Lazy Loading)**
   - 只在需要时获取数据
   - 避免无效请求

3. **智能缓存 (Smart Caching)**
   - 合理设置缓存时间
   - 避免重复请求

4. **数据关联 (Data Relations)**
   - 持仓数据与基金数据自动关联
   - 实时更新持仓中的基金数据

***

## 具体优化计划

### 优化1：创建统一的数据管理器

**新建文件：** `fund-tracker-desktop/src/stores/dataManager.ts`

**功能：**
- 统一管理所有基金数据（列表、实时数据、持仓）
- 提供数据获取、缓存、更新接口
- 处理数据关联（持仓 ↔ 基金）
- 避免重复请求

**核心设计：**
```typescript
class DataManager {
  // 统一数据存储
  fundList: string[]                    // 基金代码列表
  fundDetails: Map<string, FundDetail>  // 基金详细信息
  realtimeData: Map<string, RealtimeData> // 实时数据
  portfolio: PortfolioData              // 持仓数据
  
  // 统一获取接口
  async getFundList(): Promise<string[]>
  async getRealtimeData(codes?: string[]): Promise<RealtimeData[]>
  async getPortfolio(): Promise<PortfolioData>
  
  // 智能缓存
  private cache: Map<string, CacheEntry>
  private isFetching: Set<string>  // 防止重复请求
}
```

## 数据流设计

### 优化前数据流
```
首页 → fetchRealtimeData() → API → 存储到 fundStore
持仓 → fetchPortfolio() → API → 存储到 portfolioStore
      ↳ 再次获取基金实时数据 → API → 重复请求
```

### 优化后数据流
```
DataManager → 统一获取所有数据 → API
            ↳ 基金列表 + 实时数据 + 持仓数据
            ↳ 存储到统一缓存

各模块 → 从 DataManager 获取数据
       ↳ 有缓存用缓存，无缓存才请求
       ↳ 持仓自动关联基金实时数据
```

***

## 预期效果

1. ✅ **数据一致性** - 所有模块使用同一套数据
2. ✅ **减少请求** - 避免无效和重复请求，减少50%以上API调用
3. ✅ **提升性能** - 智能缓存，加快页面加载
4. ✅ **代码简洁** - 统一数据管理，减少重复代码
5. ✅ **易于维护** - 单一数据源，便于调试和优化
