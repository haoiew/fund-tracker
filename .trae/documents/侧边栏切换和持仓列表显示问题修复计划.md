## 问题分析与修复计划

根据您的截图和代码分析，我发现了以下问题：

***

### 问题1：侧边栏模块切换不一致

**现象：** 点击OCR识别，但页面显示的是持仓管理的内容（绿色框内显示的是持仓管理的统计卡片和表格）

**根本原因分析：**

1. **路由匹配问题**：在 `MainLayout.vue` 第35行，判断激活状态使用的是 `$route.path === `/${route.path}``，但 `route.path` 可能不包含前导斜杠

2. **路由切换问题**：`router-view` 使用了 `:key="route.path"`，但 Vue Router 的组件复用机制可能导致页面不刷新

3. **菜单路由获取问题**：第111-114行通过 `router.getRoutes()` 获取子路由，可能在某些情况下获取不到正确的路由列表

**修复方案：**

1. 修复路由激活状态判断逻辑
2. 使用 `router-link` 的 `exact` 属性或改进匹配逻辑
3. 确保 `router-view` 正确响应路由变化
4. 添加路由守卫处理特殊情况

***

### 问题2：持仓管理列表空白

**现象：** 上方统计卡片显示正常（总市值 ¥6,441.55，总盈亏 ¥-71.24，收益率 -1.09%），但下方"我的持仓"表格空白，只显示表头

**根本原因分析：**

1. **数据获取问题**：从代码看，`portfolioStore.fetchPortfolio()` 会调用 `portfolioApi.getAll()`，但可能存在以下问题：
   - 后端返回的数据结构不正确
   - `items` 数组为空或格式不对
   - 数据库中实际没有39条持仓记录，但统计显示有39只基金

2. **表格渲染问题**：
   - 表格使用了 `v-loading="portfolioStore.loading"`，可能在加载完成后没有正确渲染
   - `el-table` 的 `table-layout="auto"` 可能导致列宽计算问题
   - 数据格式可能不符合 `el-table` 的要求

3. **空状态判断问题**：第111行的空状态判断 `!portfolioStore.loading && portfolioStore.items.length === 0` 可能不正确

**数据流分析：**

```
后端 /portfolio/summary → 返回 { items: [...], stats: {...} }
前端 portfolioApi.getAll() → 调用 /portfolio/summary
前端 portfolioStore.fetchPortfolio() → 调用 portfolioApi.getAll()
前端 PortfolioView.vue → 使用 portfolioStore.items 渲染表格
```

**关键问题点：**

- 统计显示有39只基金，但表格为空，说明 `stats.item_count` 有值但 `items` 数组为空
- 这可能是后端返回的数据结构中 `items` 字段缺失或为空数组

**修复方案：**

1. **添加详细的日志输出**，追踪数据流
2. **检查后端API返回**，确保 `items` 和 `stats` 都正确返回
3. **修复表格渲染**，确保数据格式正确
4. **添加数据验证**，确保 `items` 是数组且包含有效数据
5. **改进空状态显示**，添加更详细的提示信息
