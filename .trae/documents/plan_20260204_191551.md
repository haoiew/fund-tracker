# 前后端联通性和数据源优化方案

## 目标
优化前后端代码的联通性，避免切换模块或刷新网页时重新加载所有数据，提升用户体验。

## 现状分析

### 当前问题
1. **前端无缓存** - 每次刷新都重新请求所有数据
2. **后端无缓存** - 每次请求都重新获取数据源
3. **数据源不稳定** - 网络波动导致请求失败
4. **无错误恢复** - 失败后无自动重试机制
5. **无连接性检查** - 不检查数据源可用性

### 架构问题
```
前端 → API 请求 → 后端 → 数据源（天基金/新浪/AKShare）
         ↓ 重新请求    ↓ 重新获取    ↓ 每次都请求
```

## 优化方案

#### 1.1 实现 LocalStorage 缓存

**功能**:
- 缓存基金实时数据（TTL: 60秒）
- 缓存基金历史数据（TTL: 5分钟）
- 缓存基金列表（TTL: 1小时）
- 自动过期清理
- 缓存命中统计

#### 1.2 优化 Store 层
**文件**: `fund-tracker-desktop/src/stores/fundStore.ts`

**优化**:
- 添加缓存状态管理
- 智能缓存策略（优先使用缓存）
- 缓存失效机制
- 后台静默刷新

#### 1.3 添加数据源健康检查

- 定期检查后端健康状态

## 技术栈

- **前端**: TypeScript + Pinia + LocalStorage
- **后端**: Python + FastAPI + Redis
- **监控**: 自定义监控服务
- **缓存**: Redis + LocalStorage
