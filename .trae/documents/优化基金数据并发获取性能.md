## 问题诊断

从截图可以看到多个基金显示"获取中"状态，数据源为tiantian；只有一个基金显示了最新净值，数据源为latest_nav。这说明数据源降级机制在工作，但存在性能问题。

## 核心问题

1. **批量接口内部是顺序执行**：`get_realtime_batch()` 使用 for 循环逐个获取基金数据，而非真正并发
2. **单只基金获取可能阻塞**：每个基金需要依次尝试多个数据源，超时时间累积
3. **前端体验问题**：没有显示数据源信息和加载状态

## 优化方案

### 1. 后端优化 - 真正的并发获取

修改 `fund_core_service.py` 中的 `get_realtime_batch` 方法，使用 asyncio.gather 实现真正的并发：

```python
async def get_realtime_batch_async(self, codes: List[str]) -> List[FundRealtimeData]:
    """批量获取实时数据（真正并发）"""
    tasks = [self.get_realtime_data_async(code) for code in codes]
    results = await asyncio.gather(*tasks, return_exceptions=True)
    
    valid_results = []
    for code, result in zip(codes, results):
        if isinstance(result, Exception):
            logger.error(f"获取实时数据失败 {code}: {result}")
            valid_results.append(FundRealtimeData(
                code=code,
                name=self.get_fund_name(code),
                status='获取失败'
            ))
        else:
            valid_results.append(result)
    
    return valid_results
```

### 2. 优化单只基金的数据源获取超时

在 `fund_data_source.py` 中减少单个数据源的超时时间（目前5秒太长），并增加更快的快速返回机制：

- 天天基金：5秒 → 3秒
- 腾讯基金：3秒 → 2秒  
- 新浪LOF：3秒 → 2秒
- 最新净值：作为保底，保持3秒

### 3. 前端优化 - 显示数据源和状态

修改前端表格，增加：
- 数据来源显示（天天基金/新浪LOF/最新净值等）
- 加载状态提示
- 失败重试按钮

### 4. 增加缓存预热

利用现有的 `preload_service` 在后台提前加载基金数据，减少用户等待时间。
