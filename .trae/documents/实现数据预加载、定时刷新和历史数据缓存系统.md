## 需求分析

用户提出了三个核心需求：

1. **启动时预加载数据** - 按优先级批量加载基金数据到缓存
2. **定时刷新机制** - 默认10分钟自动刷新，支持手动刷新
3. **历史数据本地缓存** - 增量更新，先显示旧数据再补充新数据

## 实现方案

### 1. 创建后台任务调度服务 (`app/services/scheduler_service.py`)

使用 `APScheduler` 实现定时任务：
- 启动时预加载默认基金列表的实时数据
- 每10分钟自动刷新缓存
- 历史数据增量更新任务

### 2. 创建数据预加载服务 (`app/services/preload_service.py`)

实现优先级队列：
- **P0 (最高)**: 用户持仓基金、关注列表基金
- **P1 (高)**: 默认基金列表
- **P2 (中)**: 最近访问过的基金
- **P3 (低)**: 其他基金

### 3. 创建历史数据管理服务 (`app/services/history_service.py`)

实现本地持久化缓存：
- SQLite 存储历史净值数据
- 增量更新策略（只获取新增日期）
- 先返回本地缓存，后台异步更新

### 4. 修改 `app/main.py`

在 lifespan 中启动调度器：
```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # 启动预加载和调度器
    await preload_service.start()
    scheduler.start()
    yield
    # 关闭时清理
    scheduler.shutdown()
```

### 5. 修改 `app/config.py`

添加新配置项：
```python
class FundDataConfig:
    PRELOAD_ENABLED: bool = True
    PRELOAD_CONCURRENT: int = 5
    REFRESH_INTERVAL_MINUTES: int = 10
    HISTORY_CACHE_DAYS: int = 365 * 2  # 2年
```

### 6. 创建 API 端点 (`app/api/v1/scheduler.py`)

提供手动刷新接口：
- `POST /scheduler/refresh` - 手动触发刷新
- `GET /scheduler/status` - 查看预加载状态
- `POST /scheduler/warmup` - 预热指定基金

## 技术细节

### 优先级预加载策略
- 使用 asyncio.Semaphore 控制并发数（默认5个）
- 按优先级分批加载，P0 立即加载，P1 延迟5秒，P2 延迟10秒
- 每批加载完成后写入 Redis 缓存

### 历史数据增量更新
- 记录每个基金的最后更新日期
- 只获取从最后日期到今天的数据
- 使用 SQLite 的 UPSERT 避免重复数据

### 前端无感刷新
- API 先返回本地缓存数据
- 后台异步更新缓存
- WebSocket 通知前端数据已更新（可选）
